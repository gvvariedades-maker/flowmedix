# LP — Mapa de capacidades (pesquisa de especialistas)

> **Objetivo:** embasar uma doc canônica de LP (`LP_CONVERSA.md`) com **design de alto impacto + conversão**, sem reinventar frameworks.  
> **Não é** o runbook operacional — é a pesquisa + matriz que a doc deve cobrir.  
> **Data da pesquisa:** 2026-07-23 · Fontes: rankings CRO 2025–2026 (Landingi, Personizely, Linear Design, YourCROExpert, Popupsmart) + frameworks primários (Unbounce, WiderFunnel/Conversion, Copyhackers, GetUplift, CXL).

---

## Critério de seleção (por que estes 10)

Prioridade para o AVANT (SaaS edtech, freemium → Pro, LP de edital `/lp/*` + home `/`):

| Critério | Peso |
|----------|------|
| Consenso em rankings CRO/LP 2025–2026 | Alto |
| Framework **nomeado e reutilizável** (não só “opinião”) | Alto |
| Cobertura de **design + copy + pesquisa + teste** (não só um eixo) | Alto |
| Aplicável a **landing page / página de oferta**, não só ecommerce genérico | Alto |
| Relevância a **identidade de público** (TE ≠ enfermeiro) e urgência de concurso | Médio |

**Excluídos de propósito** (fortes, mas fora do escopo da doc de LP): Neil Patel (SEO/geral), Pedro Sobral (tráfego pago), Érico Rocha (lançamento/infoproduto — urgência de funil pode ser citada como *inspiração*, não como método LP).

## Blueprint da doc canônica (`LP_CONVERSA.md`)

Espelhar o padrão `*_CONVERSA.md` do repo. A doc **absorve** a pesquisa; **aponta** para tokens/copy; **não** vira livro de marketing.

```text
docs/LP_CONVERSA.md          ← runbook (agente + humano)
docs/LP_RESEARCH_CAPABILITY_MAP.md  ← este arquivo (pesquisa / por quê)
```

### Estrutura proposta (seções obrigatórias)

1. **Trigger** — `LP: home` | `LP: <cidade-edital>` | `LP: polish visual`
2. **Princípios AVANT** — TE exclusivo · estudo reverso · freemium→Pro · ético (disclaimer)
3. **Brief 15 min (C7)** — persona, dor VoC, job da página, fonte de tráfego
4. **Anatomia canônica (C1–C4, C9–C15)** — ordem de seções + por quê (LIFT + CCD)
5. **Framework de copy (C5–C6)** — PAS + self-image TE + campos CMS
6. **Design de conversão (C8, C16)** — 1 CTA, contraste, demo cyber, sticky; ponte tokens
7. **Variante A — Home `/`** — arquivos + checklist
8. **Variante B — Concurso `/lp/*`** — schema CMS + urgência edital + Campina como golden
9. **Auditoria LIFT rápida (C2–C4, C11–C13)** — 6 perguntas antes de ship
10. **Anti-padrões** — CTA duplo, copy de enfermeiro, escassez falsa, drift de cor, homepage no lugar de LP
11. **Ship checklist** — visual + CRO + técnico (SEO, schema, mobile, e2e)
12. **Pós-ship (C14)** — o que medir; quando iterar
13. **Referências** — este mapa + `LANDING-AVANT-v3.md` + código

### O que **não** entra na doc (anti-monólito)

- Paleta/tokens completos → `AVANT-VISUAL-DIRECTION-v3.md`
- Copy literal da home → `lib/marketing/landingCopy.ts`
- Schema Zod completo → `lib/validations.ts` (`LpPage*`)
- Playbook de tráfego pago / Meta Ads → fora de escopo
- Moldes NeuroSlides → skill `avant-neuroslides-visual`
